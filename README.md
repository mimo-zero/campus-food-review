# 校园食堂点评推荐 🍜

> 发现新菜品 · 避开踩雷窗口 —— 面向大学生的食堂菜品评价与推荐工具

一个**纯静态**（零依赖、零构建）的 Web 应用：`index.html` + `assets/`，双击即可运行，也可直接丢到任意静态托管平台。

---

## 一、需求对照

| 题目要求 | 本实现 |
| --- | --- |
| 各食堂门店前十名的排行 | 三大类各 **TOP10 门店榜**（全站另有总榜）；每家门店内还有 **菜品 TOP10 排行**（30 家门店 × 10~11 道菜） |
| 分为三大类 | 🍚 **清淡饮食** / 🥗 **健康轻食** / 🌶️ **川渝饮食**，各自独立榜单 |
| 从排行进入匿名评论 | 榜单卡片 → 门店详情 → 菜品弹层 → 「✍️ 匿名评价」，发布后**立刻重算排名** |
| 仅学生和老师可评价 | 学号/工号首字母自动识别身份（`T`=教师、`S`=店员、其它=学生）；游客与店员的评价入口**全部禁用**并给出原因 |
| 店员不允许评论 | `App.canReview()` 前端硬拦截 + 弹层「🚫 无法评价」+ 页脚明示；评分聚合阶段 `ROLE_WEIGHT` 无店员项，**即使绕过前端也不计分** |
| 排名由学生+老师综合评分决定 | 口味35% + 分量20% + 环境15% + 服务15% + 性价比15% → 单一评价分；再按 **学生 0.6 / 教师 0.4** 加权 → 贝叶斯平滑 → 门店排名，榜单上直接展示学生分/教师分与评价数 |
| 发现新菜品 | 「新品雷达」：近 7 天被翻牌且样本 ≤12 条的菜品，按新增评价数排序 |
| 避开踩雷窗口 | 「踩雷预警」：近 30 天均分低于历史均分 0.35 以上 / 长期均分 <3.30，标红并展示历史 vs 近 30 天对比条 |

## 三、评分算法（页脚有同款说明）

```
单条评价分 = 口味×0.35 + 分量×0.20 + 环境×0.15 + 服务×0.15 + 性价比×0.15
菜品综合分 = Σ(评价分 × 角色权重) / Σ(角色权重)，角色权重：学生 0.6 / 教师 0.4 / 店员 0
           → 再做贝叶斯平滑：score = (n·avg + m·全局均分) / (n + m)   （菜品 m=3，门店 m=8）
门店综合分 = 该门店全部评价按同样公式汇总
```

平滑的作用：新开的店/新上的菜不会因为一两条五星好评就冲到榜首；样本足够后自动回归真实口碑。

## 四、体验路径

1. 打开首页 → 选择 **清淡饮食 / 健康轻食 / 川渝饮食** 分类 → 查看 TOP10。
2. 点击任意门店「进入门店 · 去评价」→ 查看菜品 TOP10 与门店评价。
3. 点某个菜品的 **评价** → 五维打分 + 文字（默认匿名）→ 提交 → toast 提示新分数，榜单即时变化。
4. 想看权限限制：右上角 **登录** → 一键体验
   - `2023010101 李思远`（学生，可评价）
   - `T1001 张老师`（教师，可评价）
   - `S2001 周师傅`（**店员，全站评价按钮置灰，弹层直接拒绝**）
5. 导航栏另有 **新品雷达 / 踩雷预警 / 我的评价**，搜索框可搜门店与菜品。

## 五、部署（保持域名不变）

站点是纯静态的，任选一家免费平台即可；**部署后把域名固定下来，后续更新直接覆盖同名文件即可，链接不变**。

**方式 A · Netlify Drop（最快，30 秒）**
1. 打开 <https://app.netlify.com/drop>
2. 把整个 `campus-canteen` 文件夹拖进去
3. 得到形如 `https://xxx-yyy.netlify.app` 的地址；站点设置里可改为你自己的子域名（如 `canteen.你的域名`），**改完保持不变即可**

**方式 B · Vercel**
1. <https://vercel.com/new> → 选择 `Other` → 把文件夹拖入 / 或连 Git 仓库（选 `campus-canteen` 目录为 Root Directory，Framework Preset 选 `Other`，不需要构建命令）
2. 得到 `https://xxx.vercel.app`，之后每次 `git push` 自动更新，域名不变

**方式 C · GitHub Pages（需要本机装 git）**
```bash
cd campus-canteen
git init && git add . && git commit -m "init"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```
仓库 `Settings → Pages → Source` 选 `main / root`，得到 `https://<用户名>.github.io/<仓库名>/`，之后 `git push` 即更新，链接永久不变。

**方式 D · Cloudflare Pages**：新建项目 → Direct Upload → 拖文件夹 → `https://<项目名>.pages.dev`。

## 六、数据说明

- 6 千余条历史评价由**确定性伪随机**在浏览器端生成（同一份代码每次生成结果完全一致），仅用于产品原型演示。
- 你发布/修改/删除的评价保存在浏览器 `localStorage`，刷新不丢；页脚的「重置演示数据」可一键清空。
- 真要上线给全校用，需要把 `App.submitReview` / `App.canReview` 换成后端接口，并在服务端再次做身份鉴权（当前的角色判定在前端，演示用途足够，正式上线必须服务端校验）。
